Darkly v2 — Audit Walkthrough

A security audit of the Darkly v2 web platform (42 Network clone): Ubuntu 24.04 + FastAPI (uvicorn) front end on :4942, PocketBase backend on :8090.

Lab setup. The sealed appliance ships as Darkly_v2.ova. It is booted in a hypervisor (VirtualBox, or QEMU/KVM as used here) with NAT port-forwards 4942→4942, 8090→8090. All testing targets the web app at http://localhost:4942 (and its backend http://localhost:8090) — the VM OS itself was never touched. Scripts assume a pristine appliance. Several exploits exfiltrate via an out-of-band listener; the guest reaches the host at 10.0.2.2 under NAT. Start tools/oob_listener.py 9900 /tmp/log first for Breach 08 (the script does this automatically).

Status note (bonus)

The platform advertises 10 flags. 7 were recovered through pure web exploitation (above). The remaining 3 are generated inside the FastAPI application behind trigger conditions that did not surface during an extensive black-box audit (every endpoint fuzzed; PocketBase DB + full backup dumped; XXE HTTP-SSRF; moderation-bot abuse; reflected XSS; /api/grades filter injection; open redirect; LFI attempts on /projects/download; base64 validation_key → /backup metadata → data/private_notes.txt; localhost port scan via SSRF). They are documented here as open leads rather than guessed.
